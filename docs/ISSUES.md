# Issue register

Branch: `hardening`. Each finding from the audit was first treated as a hypothesis and reproduced against the code as it was on `main` (commit `fb128f3`) before anything changed. The reproduction script is `tests/repro/repro-before.mjs`, and its output is `docs/evidence/repro-before.json`. The same cases are then checked against the new code by `tests/repro/repro-after.mjs`, with output in `docs/evidence/repro-after.json`.

**Status values (taken from the specification)**

- **VERIFIED FIXED**: the change is made, the acceptance test ran, and the result is recorded below.
- **IMPLEMENTED — EXTERNAL VERIFICATION REQUIRED**: the code is written and tested locally, but it cannot be confirmed without an outside party (for example a real provider or a deployed host).
- **BLOCKED — SPECIFIC DEPENDENCY**: the work cannot be finished until a named dependency exists.
- **BUSINESS VALIDATION REQUIRED**: a business, legal or tax question that no amount of code can settle.
- **NOT REPRODUCED — WITH EVIDENCE**: the finding did not reproduce, and the evidence is attached.

One item uses **OPEN**. That marks remaining engineering work. It is not one of the closing statuses, and it is listed so that nothing is silently left out.

**Test references**

- `U:` unit test in `tests/unit/`
- `S:` API test in `tests/server/`
- `E:` browser test in `tests/e2e.mjs`
- `R:` reproduction script

All results are from the runs on 2026-10-17 recorded in `docs/TEST_RESULTS.md`.
